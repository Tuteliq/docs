## What it is for

Tuteliq publishes a small, public **lexicon** of high-precision phrase patterns mapped to category flags. You can fetch it, cache it by version and run it on your side, for example to highlight a phrase for a moderator while the analysis runs.

<Warning>
**A match is a hint, not a verdict.** Still send every message for analysis, whatever the lexicon matched. A phrase alone never decides whether content is harmful, so do not skip the API call because only benign phrases matched.
</Warning>

## Endpoint

```http
GET /api/v1/prescreen/lexicon
```

**Public.** No authentication required. The lexicon contains no secrets: just patterns mapped to category tags. It's safe to fetch, cache, and inspect.

```bash
curl -i https://api.tuteliq.ai/api/v1/prescreen/lexicon
```

Response includes an `ETag` and `Cache-Control: public, max-age=3600` so SDKs that send `If-None-Match` on subsequent fetches will get a `304 Not Modified` if the lexicon hasn't changed. Lexicon version (`LEXICON_VERSION`) bumps on any entry change.

## Response shape

```json
{
  "version": "2026.05.001",
  "entries": [
    {
      "id": "groom.secrecy.our-secret-en",
      "pattern": "our little secret",
      "type": "phrase",
      "flag": "SECRECY_REQUEST",
      "weight": 0.9,
      "languages": ["en"],
      "endpoints": ["grooming"]
    },
    {
      "id": "benign.greet.hi-en",
      "pattern": "hi",
      "type": "phrase",
      "flag": "BENIGN_CONTENT",
      "weight": -1,
      "languages": ["en"],
      "endpoints": ["*"]
    }
  ]
}
```

## Matching contract

SDKs in any language re-implement the same matching contract:

| Field | Behaviour |
|---|---|
| `type: "phrase"` | Case-insensitive substring match: `text.toLowerCase().includes(pattern.toLowerCase())` |
| `type: "regex"` | JavaScript-style regex compiled with the `i` flag, tested against the original text |
| `languages` | `["*"]` matches any language; otherwise an ISO 639-1 lowercase match (`en`, `es`, `pt`, …). Default if the SDK doesn't know the language: assume `en`. |
| `endpoints` | `["*"]` applies to all; otherwise the SDK only runs entries scoped to the target endpoint (`grooming`, `distress-signals`, `bullying`, `coercive-control`, `unsafe`). |
| `weight: -1` | A phrase that is usually benign. Never a reason to skip analysis. |
| `weight: 0..1` | A phrase that often goes with the flagged category. A hint for your interface; the API does not read it from your request. |

## Privacy properties

- **The lexicon is public**: anyone can fetch and inspect it. No model weights, no proprietary scoring.
- **The matching is local**: running the lexicon sends nothing to Tuteliq.
- **Nothing is stored**: messages you send for analysis are analysed and not stored, as on every endpoint.

## What's NOT in v1

- **Multi-language entries beyond English**: coming in subsequent lexicon versions. SDKs that don't recognise the language fall back to `en` patterns; we plan to ship `es`, `pt`, `fr`, `de` next.
- **Machine-learned patterns**: v1 is curated, hand-written phrases focused on precision-per-pattern. The bar to add an entry is intentionally high.
- **Per-customer custom lexicons**: every SDK runs the same public lexicon. Custom patterns are a P3 follow-up.

## Versioning

The `version` field (e.g. `2026.05.001`) bumps on **any** change to entries. SDKs cache by version. Old SDK versions keep working with their cached lexicon; they're just less sharp until the next SDK release pulls the new one. Two-week target cadence for additions; faster for removals.

If you spot a false positive (benign content matching as a positive signal) please report it; those are the highest-priority lexicon fixes.
